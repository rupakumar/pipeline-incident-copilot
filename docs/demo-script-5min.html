2 · How it works

0:45 – 1:35

Slide 2 (the flow), then slide 3 (architecture), then slide 4 (results).

A watcher checks the pipelines every minute. When a run fails, it opens a ticket and collects evidence: the error, what changed since the last good run, and the code changes.

Then a team of AI agents built with LangGraph takes over. They classify the failure, search our runbooks and past incidents, name the root cause and propose one rerun.

The architecture has four layers: the platforms, detection, the agents, and control. Each one can be swapped. The AI model runs locally on this laptop.

We tested it on 21 real failures. It found the right cause and the right fix in all 21. No AI grades the AI; every score is checked against the known answer.

Safety is in the code, not in the prompt. A fix can only undo what changed. Low confidence goes to a person.

On slide 4: point at the three 21/21 numbers. That is the whole test set, all correct.
Files Watcher: detection/failure_watcher.py Agents graph: workflow/graph.py, agents/ Safety rule: guardrails/action/safe_actions.py Confidence: learning/confidence_calibrator.py Test: evals/runners/diagnosis_eval.py

In the form we give the workspace and the token. We test the connection, pick the jobs to watch, name the approvers who get the email, and switch auto-fix on or off. Secrets go to the macOS Keychain, not to a file.

On the Knowledge page a company uploads its own documents, like architecture docs and runbooks. They go straight into the search index, so the copilot uses them as evidence when it fixes a ticket.

4 · Live: a real auto-fix

2:25 – 3:20

Open Grafana → INC-0039. Point at the stages, the confidence (98%), the "auto · known fix" line. Then show the Gmail "auto-fixed" email.

This happened this morning on Databricks. A job ran out of memory because someone set a debug setting to 400 million rows.

The copilot found the cause with 98% confidence. It knew this exact fix had worked four times before and never failed. So it fixed it without waiting for a person, checked that the rerun passed, and sent this email.

Every fix that works becomes a memory, so next time it is faster. A fix that fails is not trusted again.

Auto-fix has strict rules: same failure, same pipeline, same fix, proven at least twice, high confidence, and the owner must switch it on.

Built this week: the cooldown is now a setting on each connection (default 1 hour). Tickets that are waiting get re-checked and auto-fixed when the rules pass. Two approvers can never approve the same ticket twice.

5 · Task 1: Claude Code skill

3:20 – 4:00

No slide. In VS Code, open the .claude/agents folder (five files) and .claude/skills/diagnose-incident/SKILL.md. Do not run it live, it takes 3–5 minutes.

The same investigation also runs inside Claude Code with one command: diagnose incident.

Five subagents work on it. Three run in parallel: triage, log analysis and knowledge search. Then one names the root cause and one plans the fix.

Each agent can only use its own read-only commands. A hook checks every call and blocks anything else. The skill can only ask for approval; it can never run a fix itself.

We also tested a hidden instruction inside an error log. The agents did not follow it, flagged it and sent it to a person.

Files Skill: .claude/skills/diagnose-incident/SKILL.md Subagents: .claude/agents/ (5 files) Hook rules: guardrails/agent/tool_policy.py Skill test: evals/runners/claude_skill_eval.py

6 · Task 2: it improves itself

4:00 – 4:40

No slide. Grafana → Self-improvement, then the digest email in Gmail.

Every night at 2:30 the copilot tests itself on real failure scenarios. Then it tries one small change to its own settings and tests again.

It keeps the change only if nothing gets worse and the score really goes up. If it is better, it goes to a git branch for an engineer to review. It never changes production on its own.

Here you can see its decisions. Today it tried two changes, saw no gain, and rejected both. That is correct: it does not ship changes it cannot prove.

Every morning it emails a short report: new tickets, fixed tickets, scores and decisions.

Files Loop: improvement/nightly.py, proposals.py, validator.py, publisher.py What it may change: config/tunables.yaml Report email: notifications/digest.py Schedule: infra/launchd/

  • What does it cost? Local model: nothing per ticket. The Claude Code skill used about $1–1.50 of usage per ticket.
