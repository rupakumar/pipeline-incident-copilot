# TCK-1012: ETL Job Failed Due to Delta Schema Mismatch

## Report

The job loghub_etl (spark logs) failed with a Delta metadata mismatch error. The error indicated a schema mismatch when writing to the Delta table, which was traced to a new cluster column being appended to the silver table without being included in its schema.

Job: `loghub_etl` (spark) · failed run: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com/?o=0000000000000000#job/1019584803253166/run/962308357848818

```
[DELTA_METADATA_MISMATCH] A metadata mismatch was detected when writing to the Delta table.
- A schema mismatch detected when writing to the Delta table (Table ID: 768f9fa0-eed5-419a-821a-2c7773d7b4a5).
To enable schema migration using DataFrameWriter or DataStreamWriter, please set: '.option("mergeSchema", "true")'.
For other operations, set the session configuration spark.databricks.delta.schema.autoMerge.enabled to "true". See the documentation specific to the operation for details.

Table schema:
```

## Timeline

- 2026-09-10 06:10 UTC — reported by dashboard owner
- First hypothesis: The schema of the silver table was outdated and missing some columns.
- Investigation: The engineer reviewed the Delta table schema and found that a new column had been added to the silver table. This column was not present in the original schema, leading to the mismatch. The fix involved evolving the silver schema to include the new column before the incremental load.
- 2026-09-10 09:10 UTC — resolved

## Root cause

A new cluster column was appended to the silver table, whose schema does not include it.

## Resolution

Evolve the silver schema (mergeSchema or ALTER TABLE ADD COLUMN) before the incremental load.
