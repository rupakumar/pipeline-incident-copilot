# TCK-1002: Job loghub_etl (hdfs logs) failed due to null event_time

## Report

The job failed because 100% of rows in the workspace had null event_time, which is above the 5% threshold. This indicates an issue with the timestamp format being used for HDFS logs.

Job: `loghub_etl` (hdfs) · failed run: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com/?o=0000000000000000#job/1019584803253166/run/766760670893668

```
AssertionError: DATA_QUALITY_FAILED: 100.00% of rows in workspace.pipeline_demo.hdfs_logs_silver have null event_time (threshold 5%). Check timestamp format / upstream log format.
assert not breaches, "DATA_QUALITY_FAILED: " + "; ".join(breaches) + "."
```

## Timeline

- 2026-07-12 06:10 UTC — reported by production support
- First hypothesis: The timestamp format in the logs is incorrect, leading to data quality issues.
- Investigation: The engineer checked the logs and found that the timestamp format used by HDFS is yyMMdd HHmmss, which does not match the expected 4-digit year format. This mismatch was the root cause of the data quality breach.
- 2026-07-12 08:10 UTC — resolved

## Root cause

timestamp_format expects a 4-digit year but HDFS logs use yyMMdd HHmmss.

## Resolution

Use yyMMdd HHmmss (the default) for HDFS logs.
