# TCK-1011: Delta Table Metadata Mismatch in ETL Job

## Report

The job loghub_etl (hdfs logs) failed due to a metadata mismatch when writing to the Delta table. The analytics team reported the issue, indicating a schema mismatch that affected the operation.

Job: `loghub_etl` (hdfs) · failed run: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com/?o=0000000000000000#job/1019584803253166/run/459206729108663

```
[DELTA_METADATA_MISMATCH] A metadata mismatch was detected when writing to the Delta table.
- A schema mismatch detected when writing to the Delta table (Table ID: 10ace647-c900-4c77-9620-e9337df55e1c).
To enable schema migration using DataFrameWriter or DataStreamWriter, please set: '.option("mergeSchema", "true")'.
For other operations, set the session configuration spark.databricks.delta.schema.autoMerge.enabled to "true". See the documentation specific to the operation for details.

Table schema:
```

## Timeline

- 2026-09-04 06:10 UTC — reported by analytics team
- First hypothesis: The schema was changed without proper migration, causing the Delta table to fail.
- Investigation: The engineer reviewed the error message and found that new columns were added to the HDFS silver table without schema evolution. This led to the Delta table metadata not matching the actual schema, causing the failure.
- 2026-09-04 08:10 UTC — resolved

## Root cause

New host_id and region columns were appended to the HDFS silver table without schema evolution.

## Resolution

Add the columns with ALTER TABLE or enable mergeSchema, then rerun.
