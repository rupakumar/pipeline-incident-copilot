# TCK-1001: Spark ETL Job Failed Due to Null Event Time

## Report

The job loghub_etl (spark logs) failed with an assertion error indicating 100% of rows in the workspace pipeline had null event_time. This suggests a mismatch between the expected timestamp format and the actual log format.

Job: `loghub_etl` (spark) · failed run: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com/?o=0000000000000000#job/1019584803253166/run/1105902828419257

```
AssertionError: DATA_QUALITY_FAILED: 100.00% of rows in workspace.pipeline_demo.spark_logs_silver have null event_time (threshold 5%). Check timestamp format / upstream log format.
assert not breaches, "DATA_QUALITY_FAILED: " + "; ".join(breaches) + "."
```

## Timeline

- 2026-07-06 06:10 UTC — reported by on-call data engineer
- First hypothesis: The issue is due to incorrect timestamp parsing in the log format.
- Investigation: The engineer reviewed the log format and found that the timestamp_format was set to MM/dd/yy, which does not match the Spark log format yy/MM/dd. This mismatch caused the event_time to be null.
- 2026-07-06 10:10 UTC — resolved

## Root cause

timestamp_format was set to MM/dd/yy, which does not match the Spark log format yy/MM/dd.

## Resolution

Remove the timestamp_format override or set it to yy/MM/dd HH:mm:ss.
