# TCK-1010: Delta Table Schema Mismatch in ETL Job

## Report

The job loghub_etl (spark logs) failed due to a schema mismatch when writing to the Delta table. A new column was added without proper schema evolution, causing the metadata to not match.

Job: `loghub_etl` (spark) · failed run: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com/?o=0000000000000000#job/1019584803253166/run/943731045396463

```
[DELTA_METADATA_MISMATCH] A metadata mismatch was detected when writing to the Delta table.
- A schema mismatch detected when writing to the Delta table (Table ID: 768f9fa0-eed5-419a-821a-2c7773d7b4a5).
To enable schema migration using DataFrameWriter or DataStreamWriter, please set: '.option("mergeSchema", "true")'.
For other operations, set the session configuration spark.databricks.delta.schema.autoMerge.enabled to "true". See the documentation specific to the operation for details.

Table schema:
```

## Timeline

- 2026-08-29 06:10 UTC — reported by production support
- First hypothesis: The schema was not updated due to a missing column in the source data.
- Investigation: The engineer reviewed the Delta table schema and found the new host_id column was appended without any schema evolution. This led to the metadata mismatch error.
- 2026-08-29 10:10 UTC — resolved

## Root cause

A new host_id enrichment column was appended to the existing silver table without schema evolution.

## Resolution

Enable schema evolution (mergeSchema) for the incremental write, or ALTER TABLE to add the column first.
